Fast Bean Copier 1.4.0 参考文档

前言

本文档是 Fast Bean Copier 的参考文档，Fast Bean Copier 是一个基于注解处理器的 Java Bean 拷贝工具，用于生成类型安全、高性能且零依赖的 Bean 映射代码。

本指南涵盖了 Fast Bean Copier 提供的所有功能。如果本指南无法回答您的所有问题，请在 GitHub Issues 中提出问题以获得帮助。

如果您在本指南中发现了错别字或其他错误，请通过在 GitHub 仓库中开启 Issue 或发送 Pull Request 来帮助我们改进。

本项目采用 Apache License 2.0 许可证。

1. 简介

Fast Bean Copier 是一个 Java 注解处理器，用于生成类型安全的 Bean 拷贝类。

您只需要定义一个目标 DTO 类并使用 @CopyTarget 注解标记它。在编译期间，Fast Bean Copier 会自动生成一个 Copier 类，该类包含 toDto() 和 fromDto() 等方法。这些方法使用普通的 Java 方法调用进行映射，不使用反射或类似的机制。

与手写映射代码相比，Fast Bean Copier 通过生成繁琐且容易出错的代码来节省时间。遵循"约定优于配置"的方法，Fast Bean Copier 使用合理的默认值，但在配置或实现特殊行为时不会妨碍您。

与动态映射框架相比，Fast Bean Copier 提供以下优势：

  • 执行速度快 - 使用普通方法调用而不是反射
  • 编译期类型安全 - 只有对象和属性能够相互映射，不会意外地将一个订单实体映射到客户 DTO
  • 清晰的编译时错误报告 - 如果：
    • 映射不完整（并非所有目标属性都被映射）
    • 映射不正确（找不到合适的映射方法或类型转换）
  • 零运行时依赖 - 生成的代码不依赖任何外部库
  • 支持集合映射 - 自动生成 List/Set 的映射方法

2. 设置

Fast Bean Copier 是基于 JSR 269 的 Java 注解处理器，可以在命令行构建（javac、Ant、Maven 等）以及 IDE 中使用。

它包含以下工件：

  • com.github.jackieonway:fast-bean-copier-annotations - 包含必需的注解，如 @CopyTarget
  • com.github.jackieonway:fast-bean-copier-processor - 包含生成 Copier 实现的注解处理器

2.1. Apache Maven

要在 Maven 项目中使用 Fast Bean Copier，请在您的 pom.xml 中添加以下依赖：

<dependency>
    <groupId>com.github.jackieonway</groupId>
    <artifactId>fast-bean-copier-annotations</artifactId>
    <version>1.4.0</version>
</dependency>

<dependency>
    <groupId>com.github.jackieonway</groupId>
    <artifactId>fast-bean-copier-processor</artifactId>
    <version>1.4.0</version>
    <scope>provided</scope>
</dependency>

注意：处理器依赖应该使用 provided 作用域，因为它只在编译时需要。

2.2. Gradle

要在 Gradle 项目中使用 Fast Bean Copier，请在您的 build.gradle 中添加以下依赖：

dependencies {
    implementation 'com.github.jackieonway:fast-bean-copier-annotations:1.4.0'
    annotationProcessor 'com.github.jackieonway:fast-bean-copier-processor:1.4.0'
}

2.3. Java 版本要求

Fast Bean Copier 需要 Java 8 或更高版本。

3. 基本使用

3.1. 定义 DTO 类

首先，定义您的源类和目标 DTO 类：

// 源类
public class User {
    private Long id;
    private String name;
    private String email;
    private Integer age;
    
    // getter/setter...
}

// 目标 DTO 类
import com.github.jackieonway.copier.annotation.CopyTarget;

@CopyTarget(source = User.class)
public class UserDto {
    private Long id;
    private String name;
    private String email;
    private Integer age;
    
    // getter/setter...
}

3.2. 编译

在编译时，Fast Bean Copier 会自动生成 UserDtoCopier 类：

mvn clean compile

生成的 Copier 类位于 target/generated-sources/annotations/ 目录下。

3.3. 使用生成的 Copier 类

编译后，您可以使用生成的 Copier 类进行对象转换：

// 单个对象拷贝
User user = new User(1L, "张三", "zhangsan@example.com", 25);
UserDto userDto = UserDtoCopier.toDto(user);

// 反向拷贝
User converted = UserDtoCopier.fromDto(userDto);

// 集合拷贝
List<UserDto> userDtos = UserDtoCopier.toDtoList(users);
Set<UserDto> userDtoSet = UserDtoCopier.toDtoSet(users);

// 反向集合拷贝
List<User> convertedUsers = UserDtoCopier.fromDtoList(userDtos);
Set<User> convertedUserSet = UserDtoCopier.fromDtoSet(userDtoSet);

4. @CopyTarget 注解

@CopyTarget 注解用于标记目标 DTO 类，指定源类和要忽略的字段。

4.1. 注解属性

@CopyTarget(
    source = User.class,           // 必需：指定源类
    ignore = {"password", "token"}, // 可选：指定要忽略的字段
    uses = {CustomConverter.class}, // 可选：自定义转换器类（v1.2）
    componentModel = ComponentModel.SPRING // 可选：依赖注入框架（v1.2）
)
public class UserDto {
    // ...
}
  • source - 源类的类型。必需。
  • ignore - 要忽略的字段名数组。可选。这些字段不会被拷贝。
  • uses - 自定义转换器类列表。可选。（v1.2 新增）
  • componentModel - 依赖注入框架选择。可选。（v1.2 新增）

4.2. 字段忽略示例

@CopyTarget(source = User.class, ignore = {"password"})
public class UserDto {
    private Long id;
    private String name;
    private String email;
    // password 字段不会被拷贝
}

5. 数据类型转换

5.1. 同名字段自动拷贝

Fast Bean Copier 自动拷贝源类和目标类中同名的字段：

public class User {
    private Long id;
    private String name;
    private String email;
}

@CopyTarget(source = User.class)
public class UserDto {
    private Long id;        // 自动从 User.id 拷贝
    private String name;    // 自动从 User.name 拷贝
    private String email;   // 自动从 User.email 拷贝
}

5.2. 基本类型与包装类型转换

Fast Bean Copier 自动支持基本类型与包装类型之间的转换：

// 源类使用基本类型
public class User {
    private long id;
    private int age;
    private double salary;
}

// 目标 DTO 使用包装类型
@CopyTarget(source = User.class)
public class UserDto {
    private Long id;        // long -> Long（自动装箱）
    private Integer age;    // int -> Integer
    private Double salary;  // double -> Double
}

反向转换时，Fast Bean Copier 会自动处理 null 值：

User user = UserDtoCopier.fromDto(userDto);
// 如果 userDto.age 为 null，则 user.age 为 0（基本类型的默认值）

6. 集合映射

6.1. List 映射

Fast Bean Copier 自动生成 List 映射方法：

// 转换为 DTO 列表
List<UserDto> dtos = UserDtoCopier.toDtoList(users);

// 反向转换
List<User> users = UserDtoCopier.fromDtoList(dtos);

6.2. Set 映射

Fast Bean Copier 自动生成 Set 映射方法：

// 转换为 DTO 集合
Set<UserDto> dtoSet = UserDtoCopier.toDtoSet(users);

// 反向转换
Set<User> userSet = UserDtoCopier.fromDtoSet(dtoSet);

6.3. 集合中的 null 处理

集合映射方法支持 null 值处理：

// 传入 null 返回 null
List<UserDto> dtos = UserDtoCopier.toDtoList(null);  // 返回 null

// 集合中的 null 元素被保留
List<UserDto> dtos = UserDtoCopier.toDtoList(Arrays.asList(user1, null, user2));
// 结果中包含 3 个元素，第二个为 null

6.4. Map 与数组深拷贝（v1.1）

  • Map：Key 通常直接拷贝（如 String/基本类型）；Value 按深拷贝规则处理，null Map/Value 保留；嵌套集合/数组递归处理。
  • 数组：按元素深拷贝，支持多维数组与 null 元素。
  • Raw/无界通配符集合将降级为浅拷贝并给出编译期警告，建议为集合声明明确泛型。
  • 生成的顶层方法：toDtoMap/fromDtoMap 保留 Key 并对 Value 做深拷贝；toDtoArray/fromDtoArray 支持数组双向转换。

7. 多字段映射（v1.2）

7.1. 多对一映射

将多个源字段合并映射到一个目标字段：

@CopyTarget(source = Person.class)
public class PersonDto {
    @CopyField(source = {"firstName", "lastName"}, 
               expression = "java(source.getFirstName() + \" \" + source.getLastName())")
    private String fullName;
}

7.2. 一对多映射

将一个源字段拆分映射到多个目标字段：

@CopyTarget(source = FullNameSource.class)
public class NameDto {
    @CopyField(source = "fullName", 
               expression = "java(source.getFullName().split(\" \")[0])")
    private String firstName;
    
    @CopyField(source = "fullName", 
               expression = "java(source.getFullName().split(\" \")[1])")
    private String lastName;
}

8. TypeConverter 类型转换器（v1.2）

8.1. 内置转换器

Fast Bean Copier 提供 6 种内置类型转换器：

转换器 源类型 目标类型 说明
NumberFormatterNumberString数字格式化
NumberParserStringNumber字符串解析为数字
DateFormatterDate/LocalDate/LocalDateTimeString日期格式化
DateParserStringDate/LocalDate/LocalDateTime字符串解析为日期
EnumStringConverterEnumString/Integer枚举转换
JsonConverterObjectStringJSON 序列化

8.2. 使用示例

@CopyTarget(source = Order.class)
public class OrderDto {
    // 数字格式化
    @CopyField(converter = NumberFormatter.class, format = "#,##0.00元")
    private String priceText;
    
    // 日期格式化
    @CopyField(converter = DateFormatter.class, format = "yyyy-MM-dd HH:mm:ss")
    private String createTimeText;
    
    // 枚举转换
    @CopyField(converter = EnumStringConverter.class)
    private String statusText;
}

10. 函数式处理增强（v1.4）

v1.4.0 引入统一的 preProcessor + postProcessor 双处理器 API，提供拷贝前和拷贝后的双重处理能力。

v1.4.0 新增：所有转换方法（toDto/fromDto/updateDto/updateEntity 及集合方法）都支持 preProcessor 和 postProcessor 双处理器。

废弃提示：beforeMapping 和 customizer 已标记为 @Deprecated，建议使用新的双处理器 API。

10.1. 双处理器 API

所有转换方法都支持两个可选的处理器参数：

  • preProcessor - 拷贝前处理器，对源对象进行预处理（可为 null）
  • postProcessor - 拷贝后处理器，对结果对象进行后处理（可为 null）

10.2. 执行顺序

preProcessor → beforeMapping（如果存在）→ 字段拷贝 → postProcessor

10.3. 单对象转换示例

// toDto 双处理器
UserDto dto = UserDtoCopier.toDto(
    user,
    source -> {
        // preProcessor: 拷贝前对 source 预处理
        source.setName(source.getName().trim());
        return source;
    },
    target -> {
        // postProcessor: 拷贝后对 target 后处理
        target.setDisplayName(target.getName().toUpperCase());
        return target;
    }
);

// fromDto 双处理器
User entity = UserDtoCopier.fromDto(
    userDto,
    source -> {
        // preProcessor: 拷贝前对 DTO 预处理
        source.setEmail(source.getEmail().toLowerCase());
        return source;
    },
    target -> {
        // postProcessor: 拷贝后对 Entity 后处理
        target.setLastSynced(Instant.now());
        return target;
    }
);

// 只使用 postProcessor（preProcessor 传 null）
UserDto dto2 = UserDtoCopier.toDto(user, null, target -> {
    target.setSource("API");
    return target;
});

// 只使用 preProcessor（postProcessor 传 null）
UserDto dto3 = UserDtoCopier.toDto(user, source -> {
    source.setName(source.getName().trim());
    return source;
}, null);

10.4. 集合转换示例

// List 双处理器
List<UserDto> dtos = UserDtoCopier.toDtoList(
    users,
    source -> {
        // preProcessor: 预处理源列表
        source.forEach(u -> u.setName(u.getName().trim()));
        return source;
    },
    target -> {
        // postProcessor: 后处理结果列表
        target.sort(Comparator.comparing(UserDto::getName));
        return target;
    }
);

// Set 双处理器
Set<UserDto> dtoSet = UserDtoCopier.toDtoSet(users, null, set -> {
    // 只使用 postProcessor 过滤结果
    return set.stream()
        .filter(dto -> dto.getId() != null)
        .collect(Collectors.toSet());
});

// Map 双处理器
Map<String, UserDto> dtoMap = UserDtoCopier.toDtoMap(userMap, null, map -> {
    map.put("default", createDefaultUserDto());
    return map;
});

// Array 双处理器
UserDto[] dtoArray = UserDtoCopier.toDtoArray(users, null, array -> {
    Arrays.sort(array, Comparator.comparing(UserDto::getName));
    return array;
});

10.5. Null 安全

当源对象为 null 时，处理器不会被调用：

UserDto dto = UserDtoCopier.toDto(null, preProcessor, postProcessor);
// dto 为 null，处理器不会执行

10.6. 迁移指南

// 旧方法（已废弃）
UserDto dto = UserDtoCopier.toDto(user, result -> {
    result.setDisplayName(result.getName().toUpperCase());
    return result;
});

// 新方法（推荐）
UserDto dto = UserDtoCopier.toDto(user, null, result -> {
    result.setDisplayName(result.getName().toUpperCase());
    return result;
});

11. 深拷贝控制（v1.4）

v1.4.0 新增 @CopyField.deepCopy 属性，用于字段级控制深拷贝行为。

11.1. 基本用法

@CopyTarget(source = Employee.class)
public class EmployeeDto {
    // 深拷贝（默认）：创建新的 AddressDto 对象
    @CopyField(deepCopy = true)
    private AddressDto address;
    
    // 浅拷贝：直接引用传递
    @CopyField(deepCopy = false)
    private DepartmentDto department;
    
    // 集合深拷贝（默认）：拷贝集合并深拷贝每个元素
    @CopyField(deepCopy = true)
    private List<ProjectDto> projects;
    
    // 集合浅拷贝：拷贝集合但元素直接引用
    @CopyField(deepCopy = false)
    private List<TagDto> tags;
}

11.2. 适用场景

deepCopy = false（浅拷贝）适用于：

  • 性能优化 - 避免不必要的对象创建
  • 共享引用 - 多个对象共享同一个引用
  • 不可变对象 - 如 String、枚举、不可变集合
  • 大对象 - 避免深拷贝大对象的开销

deepCopy = true（深拷贝，默认）适用于：

  • 独立副本 - 需要完全独立的对象副本
  • 修改安全 - 修改一个对象不影响另一个

11.3. 嵌套对象示例

// 深拷贝：调用 AddressDtoCopier.toDto() 创建新对象
@CopyField(deepCopy = true)
private AddressDto address;

// 浅拷贝：直接赋值引用
@CopyField(deepCopy = false)
private DepartmentDto department;

11.4. 集合示例

// 深拷贝：拷贝 List 并深拷贝每个 ProjectDto 元素
@CopyField(deepCopy = true)
private List<ProjectDto> projects;

// 浅拷贝：拷贝 List 但元素直接引用
@CopyField(deepCopy = false)
private List<TagDto> tags;

11.5. 数组示例

// 深拷贝：拷贝数组并深拷贝每个元素
@CopyField(deepCopy = true)
private AddressDto[] addresses;

// 浅拷贝：拷贝数组但元素直接引用
@CopyField(deepCopy = false)
private TagDto[] tags;

11.6. 默认行为

默认值为 true，保持与之前版本一致的深拷贝行为。如果需要浅拷贝，显式设置 deepCopy = false。

12. 函数式定制拷贝（v1.2 / v1.3.1，v1.4 已废弃）

支持在拷贝完成后立即执行自定义逻辑。函数类型为 java.util.function.UnaryOperator<T>，保证入参与出参一致。

⚠️ v1.4.0 废弃提示：customizer 方法已标记为 @Deprecated，建议使用 preProcessor/postProcessor 双处理器 API（见第10章）。

v1.3.1 重要变更：统一了所有集合类型的 UnaryOperator 行为。List/Set customizer 现在操作整个集合（而非单个元素），与 Map/Array 保持一致。

12.1. 支持的方法（已废弃）

⚠️ 以下方法已在 v1.4.0 标记为 @Deprecated，建议使用第10章的双处理器 API。

12.2. 单对象定制示例

// 单个对象
UserDto dto = UserDtoCopier.toDto(user, result -> {
    result.setDisplayName(result.getName().toUpperCase());
    return result;
});

// 反向转换
User entity = UserDtoCopier.fromDto(userDto, result -> {
    result.setLastSynced(Instant.now());
    return result;
});

12.3. List 集合定制示例（v1.3.1 统一行为）

v1.3.1 统一后，List customizer 操作整个列表，支持过滤、排序、限制等操作：

// 过滤列表 - 只保留价格 >= 100 的元素
List<UserDto> filteredList = UserDtoCopier.toDtoList(users, list -> 
    list.stream()
        .filter(dto -> dto.getPrice() >= 100.0)
        .collect(Collectors.toList())
);

// 排序列表
List<UserDto> sortedList = UserDtoCopier.toDtoList(users, list -> {
    list.sort(Comparator.comparing(UserDto::getName));
    return list;
});

// 限制列表大小 - 只取前 10 个
List<UserDto> limitedList = UserDtoCopier.toDtoList(users, list -> 
    list.stream().limit(10).collect(Collectors.toList())
);

// 转换为不可变列表
List<UserDto> immutableList = UserDtoCopier.toDtoList(users, 
    Collections::unmodifiableList
);

// 如果需要修改每个元素，在 customizer 中遍历
List<UserDto> modifiedList = UserDtoCopier.toDtoList(users, list -> {
    list.forEach(dto -> dto.setSource("batch"));
    return list;
});

12.4. Set 集合定制示例（v1.3.1 统一行为）

Set customizer 同样操作整个集合：

// 过滤 Set
Set<UserDto> filteredSet = UserDtoCopier.toDtoSet(userSet, set -> 
    set.stream()
        .filter(dto -> dto.getId() != null)
        .collect(Collectors.toCollection(LinkedHashSet::new))
);

// 转换为不可变 Set
Set<UserDto> immutableSet = UserDtoCopier.toDtoSet(userSet, 
    Collections::unmodifiableSet
);

12.5. Map 集合定制示例（v1.3.1 新增）

Map customizer 操作整个 Map：

// 过滤 Map - 移除 null 值条目
Map<String, UserDto> filteredMap = UserDtoCopier.toDtoMap(userMap, map -> {
    map.entrySet().removeIf(entry -> entry.getValue() == null);
    return map;
});

// 转换为不可变 Map
Map<String, UserDto> immutableMap = UserDtoCopier.toDtoMap(userMap, 
    Collections::unmodifiableMap
);

// 添加额外条目
Map<String, UserDto> enrichedMap = UserDtoCopier.toDtoMap(userMap, map -> {
    map.put("default", createDefaultUserDto());
    return map;
});

12.6. Array 数组定制示例（v1.3.1 新增）

Array customizer 操作整个数组：

// 过滤数组 - 移除 null 元素
UserDto[] filteredArray = UserDtoCopier.toDtoArray(users, array -> 
    Arrays.stream(array)
        .filter(dto -> dto != null && dto.getId() != null)
        .toArray(UserDto[]::new)
);

// 排序数组
UserDto[] sortedArray = UserDtoCopier.toDtoArray(users, array -> {
    Arrays.sort(array, Comparator.comparing(UserDto::getName));
    return array;
});

// 限制数组大小
UserDto[] limitedArray = UserDtoCopier.toDtoArray(users, array -> 
    Arrays.copyOf(array, Math.min(10, array.length))
);

12.7. null 安全

当源对象为 null 时，customizer 函数不会被调用：

UserDto dto = UserDtoCopier.toDto(null, result -> {
    // 这里不会执行
    return result;
});
// dto 为 null

List<UserDto> list = UserDtoCopier.toDtoList(null, result -> {
    // 这里不会执行
    return result;
});
// list 为 null

13. 自定义转换器（v1.2）

13.1. 使用 uses 引入转换器

通过 @CopyTarget 的 uses 属性引入自定义转换器类：

// 步骤1：定义转换器类
@Component
public class StringToListConverter {
    public List<String> stringToList(String str) {
        if (str == null) return null;
        return Arrays.asList(str.split(","));
    }
    
    public String listToString(List<String> list) {
        if (list == null) return null;
        return String.join(",", list);
    }
}

// 步骤2：在 @CopyTarget 中使用
@CopyTarget(source = User.class, uses = {StringToListConverter.class})
public class UserDto {
    @CopyField(source = "tags", qualifiedByName = "stringToList")
    private List<String> tagList;
}

13.2. 使用 qualifiedByName 绑定方法

通过 qualifiedByName 指定要调用的转换方法名：

@CopyTarget(source = Person.class, uses = {PersonConverter.class})
public class PersonDto {
    @CopyField(qualifiedByName = "formatAge")
    private String ageText;
    
    @CopyField(qualifiedByName = "statusToName")
    private String statusText;
}

14. 更新现有对象（v1.3）

v1.3 新增 updateDto 和 updateEntity 方法，用于更新已存在的对象，而不是创建新对象。

14.1. updateDto 方法

更新已存在的目标 DTO 对象：

// 创建已存在的 DTO 对象
UserDto existingDto = new UserDto();
existingDto.setName("原始名称");
existingDto.setEmail("old@example.com");

// 使用源对象更新 DTO
User user = new User(1L, "新名称", "new@example.com", 25);
UserDtoCopier.updateDto(existingDto, user);

// existingDto 的字段被更新为 user 的值
// existingDto.getName() -> "新名称"
// existingDto.getEmail() -> "new@example.com"

14.2. updateEntity 方法

更新已存在的实体对象（反向更新）：

// 创建已存在的实体对象
User existingUser = new User();
existingUser.setName("原始名称");

// 使用 DTO 更新实体
UserDto userDto = new UserDto(1L, "新名称", "new@example.com", 25);
UserDtoCopier.updateEntity(existingUser, userDto);

// existingUser 的字段被更新为 userDto 的值

14.3. 嵌套对象更新

支持嵌套对象的递归更新：

@CopyTarget(source = Order.class)
public class OrderDto {
    private Long id;
    private AddressDto address;  // 嵌套对象
}

// 更新时，嵌套对象也会被递归更新
OrderDto existingDto = new OrderDto();
existingDto.setAddress(new AddressDto());  // 已存在的嵌套对象

Order order = new Order();
order.setAddress(new Address("北京", "朝阳区"));

// existingDto.address 的字段被更新，而不是替换整个对象

14.4. Null 值处理

源对象为 null 时，不修改目标对象：

UserDto existingDto = new UserDto();
existingDto.setName("原始名称");

UserDtoCopier.updateDto(existingDto, null);
// existingDto 保持不变，name 仍为 "原始名称"

15. 映射前回调（v1.3，v1.4 已废弃）

v1.3 新增 beforeMapping 属性，用于在映射逻辑执行之前调用指定的回调方法。

⚠️ v1.4.0 废弃提示：beforeMapping 已标记为 @Deprecated，建议使用 preProcessor 替代（见第10章）。

15.1. 基本用法

@CopyTarget(source = User.class, beforeMapping = "validateAndPrepare")
public class UserDto {
    private Long id;
    private String name;
    
    // 映射前回调方法（必须是 default 方法）
    default void validateAndPrepare(User source) {
        if (source.getName() == null) {
            throw new IllegalArgumentException("Name cannot be null");
        }
        // 可以进行验证、初始化、日志记录等操作
    }
}

15.2. 方法签名要求

  • 必须是目标类中的 default 方法
  • 参数类型为源类类型
  • 返回类型为 void

15.3. 使用场景

  • 验证：在映射前验证源对象的有效性
  • 初始化：准备映射所需的资源或状态
  • 日志记录：记录映射操作的开始
  • 审计：记录数据转换的审计信息

16. 条件映射（v1.3）

v1.3 新增 condition 属性，用于指定条件表达式，决定是否执行字段映射。

16.1. 基本用法

@CopyTarget(source = User.class)
public class UserDto {
    // 只有当源字段不为 null 时才映射
    @CopyField(condition = "java(source.getName() != null)")
    private String name;
    
    // 只有当年龄大于 0 时才映射
    @CopyField(condition = "java(source.getAge() != null && source.getAge() > 0)")
    private Integer age;
}

16.2. 表达式格式

条件表达式使用 java(...) 格式包裹 Java 表达式：

// 简单 null 检查
@CopyField(condition = "java(source.getEmail() != null)")
private String email;

// 复杂条件
@CopyField(condition = "java(source.getStatus() != null && source.getStatus().isActive())")
private String statusText;

// 字符串非空检查
@CopyField(condition = "java(source.getPhone() != null && !source.getPhone().isEmpty())")
private String phone;

16.3. 与其他属性组合

条件映射可以与 expression、converter 等属性组合使用：

@CopyField(
    condition = "java(source.getPrice() != null)",
    converter = NumberFormatter.class, 
    format = "#,##0.00"
)
private String priceText;

17. 默认值和常量（v1.3）

v1.3 新增 defaultValue 和 constant 属性，用于设置默认值和常量值。

17.1. 默认值（defaultValue）

当源字段为 null 时使用默认值：

@CopyTarget(source = User.class)
public class UserDto {

    @CopyField(defaultValue = "未知")

    // 数字类型默认值
    @CopyField(defaultValue = "0")

    // 布尔类型默认值
    @CopyField(defaultValue = "false")

}

17.2. 支持的默认值类型

目标类型 默认值示例 说明
String"默认文本"直接使用字符串

Long"0"自动解析为长整数

19. Null 值处理策略（v1.3）

v1.3 新增 NullValueStrategy 枚举，用于控制 null 值的处理方式。

19.1. 策略说明

策略 行为 使用场景
IGNORE 忽略 null 值，不更新目标字段 部分更新，保留目标对象的原有值
REPLACE 替换 null 值，将目标字段设置为 null 完全覆盖，源对象的 null 值也要同步

19.2. 使用示例

// 包级别配置

existingDto.setEmail("old@example.com");

user.setName("新名称");
user.setEmail(null);  // email 为 null

UserDtoCopier.updateDto(existingDto, user);
// existingDto.name -> "新名称"（被更新）
// existingDto.email -> "old@example.com"（保持不变，因为源值为 null）

19.3. REPLACE 策略示例

// 包级别配置
@CopyTargetConfig(nullValueStrategy = NullValueStrategy.REPLACE)
package com.example.dto;

// 使用 REPLACE 策略

existingDto.setEmail("old@example.com");

user.setName("新名称");

UserDtoCopier.updateDto(existingDto, user);
// existingDto.name -> "新名称"（被更新）
// existingDto.email -> null（被设置为 null）

20. 嵌套对象深拷贝（v1.3.2）

v1.3.2 新增嵌套对象深拷贝功能，自动处理不同类型的嵌套对象转换。

20.1. 基本用法

当源对象和目标对象的嵌套字段类型不同时，框架会自动进行深拷贝转换：

// 实体类
public class Employee {
    private Long id;
    private String name;
    private Address address;  // 嵌套对象
}

// DTO 类
@CopyTarget(source = Employee.class)
public class EmployeeDto {
    private Long id;
    private String name;
    private AddressDto address;  // 不同类型的嵌套对象
}

// 使用
Employee employee = new Employee(1L, "张三", new Address("北京", "朝阳区"));
EmployeeDto dto = EmployeeDtoCopier.toDto(employee);
// dto.address 自动转换为 AddressDto 类型

20.2. 智能 Copier 检测

框架会智能检测嵌套对象是否有对应的 Copier 类：

方式 1：使用 Copier（推荐，最优性能）

// 为嵌套对象添加 @CopyTarget 注解
@CopyTarget(source = Address.class)
public class AddressDto {
    private String city;
    private String street;
}

// 生成的代码会使用 AddressDtoCopier
target.setAddress(AddressDtoCopier.toDto(source.getAddress()));

方式 2：字段级拷贝（自动回退）

// 如果 AddressDto 没有 @CopyTarget 注解
public class AddressDto {
    private String city;
    private String street;
}

// 生成的代码会使用字段级递归拷贝
AddressDto nestedAddressDto = new AddressDto();
nestedAddressDto.setCity(source.getAddress().getCity());
nestedAddressDto.setStreet(source.getAddress().getStreet());
target.setAddress(nestedAddressDto);

20.3. 多层级嵌套

支持任意深度的对象图，混合使用 Copier 和字段级拷贝：

// 层级 1：有 @CopyTarget
@CopyTarget(source = Company.class)
public class CompanyDto {
    private Long id;
    private DepartmentDto department;  // 层级 2
}

// 层级 2：无 @CopyTarget（使用字段拷贝）
public class DepartmentDto {
    private String name;
    private ManagerDto manager;  // 层级 3
}

// 层级 3：有 @CopyTarget（在字段拷贝中也能使用 Copier）
@CopyTarget(source = Manager.class)
public class ManagerDto {
    private String name;
    private AddressDto address;  // 层级 4
}

// 层级 4：有 @CopyTarget
@CopyTarget(source = Address.class)
public class AddressDto {
    private String city;
    private String street;
}

// 使用
Company company = new Company(1L, 
    new Department("技术部", 
        new Manager("李四", 
            new Address("上海", "浦东新区"))));
CompanyDto dto = CompanyDtoCopier.toDto(company);
// 所有层级的嵌套对象都会被正确转换

20.4. Null 安全

所有嵌套对象拷贝都包含 null 检查：

Employee employee = new Employee(1L, "张三", null);  // address 为 null
EmployeeDto dto = EmployeeDtoCopier.toDto(employee);
// dto.address 为 null，不会抛出 NullPointerException

20.5. 性能建议

  • 频繁使用的嵌套对象：添加 @CopyTarget 注解，使用 Copier 获得最优性能
  • 简单或一次性嵌套对象：无需注解，使用字段级拷贝即可
  • 避免过深嵌套：建议对象图深度 < 5 层
  • 不支持循环引用：框架不处理循环对象图

21.1. 对象级别的 null 处理

24. 故障排除

24.1. 生成的代码未出现

问题：编译后在 target/generated-sources/annotations/ 中找不到生成的 Copier 类。

解决方案：

  1. 确保使用了 @CopyTarget 注解
  2. 确保源类和目标类都有 getter/setter 方法
  3. 运行 mvn clean compile 进行完整编译

24.2. 字段未被拷贝

问题：某些字段在拷贝后为 null。

解决方案：

  1. 检查字段名是否完全相同（区分大小写）
  2. 检查源类和目标类是否都有该字段的 getter/setter
  3. 检查该字段是否在 ignore 属性中

24.3. 类型转换错误

问题：编译时出现类型不兼容的错误。

解决方案：

  1. 检查源类和目标类的字段类型是否兼容
  2. 对于不兼容的类型，在应用层手动处理

25. 性能考虑

25.1. 编译期代码生成

Fast Bean Copier 在编译期生成代码，因此：

  • 运行时性能与手写代码相同
  • 无反射开销
  • 无动态代理开销
  • 直接调用 getter/setter

25.2. 内存使用

生成的 Copier 类是无状态的，可以安全地在多线程环境中使用。

27. 常见问题

Q: 支持哪些 Java 版本？

A: Java 8 及以上版本。

Q: 支持嵌套对象拷贝吗？

A: 支持。同名字段会直接拷贝。对于不同类型的嵌套对象，需要在应用层手动处理或为嵌套对象也定义 @CopyTarget。

Q: 集合与数组的深拷贝支持到什么程度？

A: 1.1 版本内置 List/Set/Map/数组的双向深拷贝，支持嵌套组合（例如 List<List<User>>、Map<String, List<User>>、多维数组），并对原始类型或无界通配符自动降级为安全的浅拷贝。

Q: 有哪些性能与使用建议？

A: 生成代码已为集合预分配容量并避免反射。实际使用中建议：

  1. 始终为集合声明明确的泛型参数，避免原始类型；
  2. 需要双向转换时同时定义 DTO 与源类的 @CopyTarget；
  3. 发布前执行 mvn clean compile, mvn test, mvn jacoco:report 验证兼容性与覆盖率（示例模块覆盖率可达 90%+）。

Q: 支持自定义转换器吗？

A: 支持（v1.2.0+）。可以使用内置 TypeConverter 或自定义转换器类。

Q: 支持依赖注入吗？

A: 支持（v1.2.0+）。通过 componentModel 属性选择 Spring、CDI 或 JSR-330。

Q: 生成的代码在哪里？

A: 在 target/generated-sources/annotations/ 目录下。

Q: 可以在 IDE 中看到生成的代码吗？

A: 可以。大多数 IDE（如 IntelliJ IDEA、Eclipse）都会自动识别生成的源代码。

Q: 生成的代码是否线程安全？

A: 是的。生成的 Copier 类是无状态的，可以安全地在多线程环境中使用。

Q: 支持 Lombok 吗？

A: 支持。Fast Bean Copier 可以与 Lombok 一起使用，Lombok 会生成 getter/setter 方法。

Q: 支持 Builder 模式吗？

A: 当前版本不支持。Copier 类使用 setter 方法进行赋值。
